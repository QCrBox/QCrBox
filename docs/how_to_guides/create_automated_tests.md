# Creating Automated Tests for QCrBox Applications

This guide explains how to create automated test suites for your QCrBox applications using the `qcrbox-test` tool. Automated testing ensures your application commands work as expected and helps prevent regressions.

## Prerequisites

- A working QCrBox installation
- The `qcrbox-test` tool installed (usually part of the QCrBox development environment)
- Your application configuration file (e.g., `config_my_app.yaml`), as generated by `qcb init`.
- A valid CIF file to use as a test input, that should result in a successful execution.

## Step 1: Initialize a Test Suite

The easiest way to start is by using the `init` of `qcrbox-test` command. This will generate a template test suite based on your application's configuration.

```bash
qcrbox-test init --config services/applications/my_app/config_my_app.yaml --valid_cif path/to/test_structure.cif --output services/applications/my_app/test_my_app.yaml
```

This command reads your application configuration to understand available commands and parameters, and creates a YAML file with placeholder test cases for each command. 
It will also copy the CIF file to a `test_cif_files` subdirectory for use in the tests.

## Step 2: Configure Test Cases

Open the generated YAML file. You will see a structure like this:

```yaml
application_slug: my_app
application_version: "1.0.0"
test_cases:
  - name: "Test command_name"
    command_name: command_name
    input_parameters:
      - name: input_cif
        type: external_file
        value: "./test_cif_files/structure.cif"
      # ... other parameters
    expected_results:
      - result_type: status
        expected: successful
```

### Define Input Parameters

For each test case, ensure the `input_parameters` are correct.
- **External Files**: If your command takes one or more file inputs (such as a CIF file, or any other format), ensure the `value` points to a valid file relative to the YAML file (e.g. in a `test_cif_files` or `test_data` subdirectory).
  If the single file you gave at initialization is not sufficient, add more files to the directory and reference them here.
- **Internal Files**: For small test inputs (like simple CIF structures, configuration snippets, or small data files), you can embed the file content directly in the YAML using the `|` block scalar. This is useful for keeping tests self-contained.
  ```yaml
  - name: input_cif
    type: internal_file
    value: |
      data_test
      _cell.length_a 10.0
      # ... rest of file content
  ```
- **Simple Values**: Set appropriate string, integer, or boolean values for other parameters.

### Add Assertions

The default template checks if the command runs successfully. You should add more specific assertions to verify the output.

**Example: Checking a specific value**

```yaml
    expected_results:
      - result_type: status
        expected: successful
      
      # Check that the cell length A is correct
      - result_type: cif_value
        test_type: match
        cif_entry_name: "_cell.length_a"
        expected_value: 10.5
```

**Example: Checking a value in a loop**

```yaml
      # Check the occupancy of atom O1
      - result_type: cif_loop_value
        test_type: match
        cif_entry_name: "_atom_site.occupancy"
        row_lookup:
          - row_entry_name: "_atom_site.label"
            row_entry_value: "O1"
        expected_value: 1.0
```

See the [Test Suite Format](../technical_reference/command_tester/test_suite_format.md) reference for all available test types.

## Step 3: Run the Tests

Run your test suite using the `qcrbox-test` command:

```bash
qcrbox-test --test-location services/applications/my_app/test_my_app.yaml
```

If you have multiple test files in a directory, you can run them all:

```bash
qcrbox-test --test-location services/applications/my_app/
```

## Step 4: Debugging Failures

If a test fails, use the `--debug` flag to get more information:

```bash
qcrbox-test --test-location services/applications/my_app/test_my_app.yaml --debug
```

This will create a directory (by default `qcrbox_cmd_tester/logs/`) containing:

- `summary.log`: Detailed error messages and failure reasons.
- `test_result.cif`: The actual output CIF file from the command.

You can also specify a custom directory for logs:

```bash
qcrbox-test --test-location services/applications/my_app/test_my_app.yaml --debug --log-dir ./my_logs
```

You can inspect the `test_result.cif` to see why your assertions failed (e.g., if the value was different than expected).

## Best Practices

- **Organize Test Files**: Keep your test YAML files in your application's directory (e.g., `services/applications/my_app/`).
- **Test Data**: Store input CIF files in a subdirectory relative to the test file, e.g., `services/applications/my_app/test_cif_files/`.
- **Comprehensive Testing**: Test both success cases and expected failure cases (e.g., invalid input).
- **Version Control**: Commit your test suites and test data to your repository.
